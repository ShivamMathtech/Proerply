# API guide

Interactive OpenAPI documentation is available at `/docs`, and `/openapi.json` is generated by FastAPI. All application endpoints are under `/api/v1`.

## Session flow

1. `POST /auth/register` with `{name,email,password}` or `POST /auth/login` with `{email,password}` returns `{user,csrfToken}` and sets an HttpOnly session cookie.
2. Send that cookie on future requests. Send `X-CSRF-Token` on every protected POST/PATCH/PUT/DELETE request.
3. After a page refresh, `GET /auth/session` returns the current user and CSRF token. The frontend adapter obtains it when needed.
4. `POST /auth/refresh` rotates the session. `POST /auth/logout` revokes it.

Public auth endpoints still enforce allowed origins and rate limits. Invalid credentials return 401; role/CSRF failures return 403; unavailable records return 404; conflicts return 409; validation failures return 422.

## Endpoints

| Area | Routes | Access |
|---|---|---|
| Health | `GET /health` | Public |
| Auth | register, login, session, refresh, logout, forgot-password, verify-reset-code, reset-password under `/auth` | Depends on operation |
| Catalog | `GET /courses`, `/courses/search`, `/courses/{id}`, `/categories`, `/instructors` | Public; draft visibility restricted |
| Lessons | `GET /courses/{id}/lessons` | Enrolled learner |
| Workspace | `GET /workspace` | Returns empty anonymous state or current user's data |
| Profile | `GET/PATCH /users/me`, `GET /users/{id}` | Signed in; public output respects profile privacy |
| History | `GET/POST/DELETE /search-history` | Current user |
| Enrollment | `POST /enrollments`, `GET /enrollments/me` | Current user; paid enrollment requires verified order |
| Progress | `GET /progress`, `PUT /progress/{lessonId}` | Current enrolled user |
| Assessments | `GET /quizzes/{id}`, `POST /quizzes/{id}/submit`, `GET /assessments` | Current enrolled user |
| Reminders | `GET/POST /reminders`, `PATCH/DELETE /reminders/{id}` | Owner |
| Chat | `GET/POST /conversations`, `GET/POST /conversations/{id}/messages`, `POST /conversations/{id}/read` | Conversation member |
| Awards | `GET /achievements`, `GET /certificates` | Current user |
| Notifications | `GET /notifications`, `POST /notifications/{id}/read` | Owner |
| Payments | `POST /payments/checkout`, `GET /payments/orders` | Current user |
| Provider events | `POST /payments/webhook` | Valid Stripe signature required |
| Studio | `GET /admin/analytics`, `GET /admin/courses`, `PUT /admin/courses/{id}`, `GET /admin/badges` | Administrator or course-owning instructor |
| Administration | `PATCH /admin/users/{id}`, `POST /admin/categories`, `PUT /admin/instructors/{id}`, `PUT /admin/badges/{id}`, `GET /admin/conversations`, `DELETE /admin/conversations/{cid}/messages/{mid}` | Administrator |
| Calls | `GET /calls/config`, `GET/POST /calls/{conversationId}` | Conversation member |

Course search supports `q`, `category`, `level`, `rating`, `duration=short|long`, `price=free|paid`, `sort=rating|popular|price|price-desc`, `offset`, and `limit` (1–100). Short means up to 60 minutes. Message history supports `offset` and `limit` (1–200). The chat UI loads the most recent 200 messages per conversation; analytics displays the latest 500 payment records. These are bounded small-deployment interfaces, not unbounded reporting exports.

## Example payloads

```json
{"courseId":"react"}
```

```json
{"completed":true,"position":25}
```

```json
{"answers":{"react-q1":0,"react-q2":1,"react-q3":2,"react-q4":3}}
```

```json
{"title":"Study React","dueAt":"2030-01-01T10:00:00+05:30","description":"A focused session","completed":false}
```

```json
{"text":"Could you explain the exercise?"}
```

Reminder timestamps require an explicit timezone and are normalized to UTC; the browser displays the device's local time. Course IDs, enrollment owners, quiz scores and order amounts are resolved by the server rather than trusted from arbitrary client fields.
